## 1. Problem and requirements

When a URL check failed, the preview could continue showing an old successful report beside the new error, confusing which URL the report described.

## 2. Implementation

Cleared stale report data on failed checks. Existing results remain visible while a new check is loading, and the address bar updates only after a successful check.

## 3. Validation

PR-reported: `npm run check` passed (0 errors, 0 warnings, 10 hints); 620 tests passed before one unrelated agenda rendering test timed out; `npm run build` and `git diff --check` passed. Local dev checks covered a valid Hugo URL followed by a 404 URL. In review, the maintainer also verified an offline/network failure and a subsequent successful check.

## 4. Maintainer review

Anurag629 approved after verifying the 404 showed only the error, the address bar retained the last successful URL, a later successful check restored the report, and offline mode showed “Failed to fetch” without stale results. The network failure case had not been tested by the contributor before review.

## 5. What I learned

- Error, loading, and success transitions should each define which prior data remains visible. State and URL updates should correspond to the latest successful result.
