## 1. Problem and requirements

Minimal Player treated progress 0 like a missing value and invalid non-numeric input could produce a server error.

## 2. Implementation

Changed progress parsing so zero stays zero; missing, empty, and non-finite values fall back to 35; values clamp to 0–100. Added regression tests for zero, default, invalid, and out-of-range values.

## 3. Validation

PR-reported: `npm run check` passed with 0 errors and warnings; 753 tests passed across 34 files; build and `git diff --check` passed. In dev, progress 0 produced an empty bar and `progressPercent=abc` returned HTTP 200. Maintainer verification on current `dev` reported 878 tests and build passing.

## 4. Maintainer review

Anurag629 approved after checking that invalid progress returned 200 and zero rendered an empty bar. The PR description had a local screenshot-path placeholder, so the maintainer verified the editor directly and asked for future screenshots to be attached rather than referenced by a local path.

## 5. What I learned

- Zero is a valid boundary value and must not be conflated with absent input. Validate numeric, empty, non-finite, and out-of-range cases independently.
